What anytrack does

anytrack takes a video of flies in one or more circular arenas and produces a per-frame trajectory table (one row per animal per frame: centroid, body-axis angle, ellipse size, kinematics). It auto-detects the arenas, builds a static background, and tracks each fly by background subtraction + a Kalman/nearest-neighbour linker.

Optionally (Milestone B), it estimates keypoint pose (head, thorax, abdomen tip, left/right wing) on a small crop around each tracked centroid, using a SLEAP (sleap-nn) model you label and train from within the package.

Install

The project is uv-managed. From the repo root:

uv sync                       # core install (tracking + QC + labelling GUI)

That gives you the whole classical pipeline and the labelling GUI. The pose training/inference backend is heavy and optional — install it only when you want to train or run pose:

uv pip install --prerelease=allow 'sleap-nn[torch]' sleap-io   # pose backend (needs Python >= 3.11)
ffmpeg is used for fast decoding/encoding (preprocessing and QC overlays). If it is not on your PATH, the pipeline falls back to OpenCV where possible.

Inputs

  • Video — e.g. /data/flies/experiment.avi.
  • Timing CSV — a per-frame timing table, by default the video path with a .csv suffix (/data/flies/experiment.csv). Pass --timing to point elsewhere.

1 · Track

Two ways to run tracking:

GUI

uv run anytrack

Open a video, let it detect arenas, hit Run tracking, then inspect the overlay and results table. Good for exploring one video and tuning parameters.

Headless (batch / scripting)

uv run anytrack-run \
  --video /data/flies/experiment.avi \
  --output /data/flies/results/

A directory --output auto-names the file experiment_tracks.parquet inside it; a .parquet/.csv path is used as-is. Fast mode (parallel per-ROI tracking) is the default; use --no-fast for the single-pass path, or --downscale/--workers to tune fast mode.

Batch mode. Pass a directory to --video and anytrack discovers the videos in it, validates each (openable + timing CSV), then asks "Process all N videos? [Y/n]" — answer n for a checkbox selector. Videos run one at a time (each already parallelizes across ROIs). Same for anytrack-label, where --tracks/--labels become directories resolved per video (<stem>_tracks.parquet / <stem>_labels.json).

Output columns (long format, one row per animal per frame):

columnmeaning
roi, track_idarena name (numbered left→right, top→bottom) and animal id
frame, t_sframe index and time (s)
x, ycentroid, full-frame pixels (canonical)
x_roi, y_roicentroid relative to the arena's bounding box
angle_deg, major, minor, areafitted body ellipse
kinematicsspeed etc., in mm using arena_diameter_mm

2 · Quality control (QC)

QC writes an annotated overlay video, diagnostic plots, per-frame failure flags, a summary, and a single qc_report.html. Add it to a run, or generate it from an existing tracks file.

# during a run
uv run anytrack-run --video /data/flies/experiment.avi --output /data/flies/results/ --qc

# from a finished tracks table
uv run anytrack-qc \
  --video /data/flies/experiment.avi \
  --tracks /data/flies/results/experiment_tracks.parquet \
  --out-dir /data/flies/results/qc

The overlay is downscaled and rendered every 5th frame by default (fast, small). Options:

  • --qc-full — full resolution, every frame (large, slow).
  • --qc-overlay-stride N — render every Nth frame.
  • --crop-roi arena_02 — crop the overlay to one arena.
  • --follow arena_02 (with --follow-size) — a "fly-cam" window that follows one track's centroid. The source region is scaled up to --crop-size (default 800²) before annotations are drawn, so the overlay stays crisp.

3 · Pose optional · Milestone B

Pose runs on top of a finished track: crop → keypoint model → per-frame keypoints. The workflow is label → train → infer. It needs the pose backend installed (see Install). For getting a good model (how much to label, the active-learning loop, fixing wing-swap), see the training guide.

3a · Label

Sample a diverse set of frames and hand-place keypoints. The GUI seeds points from the tracked ellipse, so you mostly nudge rather than click from scratch.

uv run anytrack-label \
  --video /data/flies/experiment.avi \
  --tracks /data/flies/results/experiment_tracks.parquet \
  --labels /data/flies/results/experiment_labels.json \
  --n 100

It saves a native JSON store (autosaves; rerun with just --labels to resume). Keyboard-first:

keysaction
1–5select keypoint · click to place (auto-advances)
dragnudge a placed point
v / w / btoggle visible / swap wings / mark bad frame
, . / 0scrub the ±context window to read dynamics / back to anchor
← → · Space · Ctrl-Sprev/next sample · confirm+next · save

Aim for ~100–200 frames spread across arenas and poses; wing L/R is the hardest for the model, so label plenty of wing-out frames.

3b · Train

uv run anytrack-train \
  --labels /data/flies/results/experiment_labels.json \
  --run-name fly5_v1 --epochs 50 --device mps

This exports the labels to .slp and trains a sleap-nn centered-instance model, writing it to <labels dir>/models/fly5_v1. On Apple Silicon use --device mps.

3c · Infer

uv run anytrack-run \
  --video /data/flies/experiment.avi \
  --output /data/flies/results/ \
  --pose --pose-model /data/flies/results/models/fly5_v1 \
  --pose-device mps --qc

Produces experiment_pose.parquet (long format: roi, track_id, frame, t_s, keypoint, x_full, y_full, x_roi, y_roi, x_crop, y_crop, score, out_of_bounds). With --qc the overlay gains the coloured skeleton, plus a keypoint confidence plot and pose flags (low-confidence, missing, wing-swap, head/tail flip).

Sparse pose. Pose is the slow stage. Use --pose-every-n 5 to run pose on every 5th frame (roughly 5× faster wall-time); combine with a matching --qc-overlay-stride 5 for a flicker-free overlay.

3d · Benchmark (optional)

uv run anytrack-bench --pose \
  --video /data/flies/experiment.avi \
  --tracks /data/flies/results/experiment_tracks.parquet \
  --model /data/flies/results/models/fly5_v1 \
  --devices mps,cpu --batches 4,16 --every-n 1,5

Reports crops/s across device × batch × every_n and a decode floor. Bigger pose_batch_size is markedly faster on MPS (≈3× from 4→16) and is applied automatically on real runs.

Configuration

Settings live in a TOML file at the platform config dir (created on first run; the GUI and anytrack-run read it). Most tracking flags can be set there or overridden per-run on the CLI. Notable fields:

fieldwhat
fast_mode, roi_downscale, n_tracking_workersfast-path tracking
arena_diameter_mmarena size for mm/px kinematics scaling
max_jump_px, miss_tolerance, detect_max_candidateslinker robustness
crop_sizepose crop size (px), default 96
pose_node_colorslabel/overlay colours: "head:#ff5252,thorax:#ffd740,…"
pose_batch_size, pose_device, pose_every_npose speed/coverage
qc_overlay_stride, qc_crop_output_sizeQC overlay defaults

Tips & gotchas

  • Arena numbering is left→right, top→bottom (arena_01 = top-left).
  • Pose needs a trained model. --pose with the sleap-nn backend errors if no --pose-model is given.
  • 30 labels is a pilot. Expect a rough model; ~100–200 labelled frames give good keypoints. Watch the QC wing-swap rate — a high rate means the model needs more wing labels.
  • Cropped overlays: use --follow for a fly-centred view (works even without arena geometry); --crop-roi shows the whole arena when run from a full session.
  • Slow/network storage: set stage_video_locally to copy the video to local disk before processing.
