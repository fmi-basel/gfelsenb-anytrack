The goal & where we stand

A "good" model here means: on a held-out clip, the QC skeleton overlay looks right frame-by-frame, keypoint confidence is high, and the pose flags are low — especially wing-swap, which is the hard part for a fly.

Baseline (pilot). The 30-frame fly5_v1 model already had high confidence (median score ≈ 0.98) but a ~14% wing-swap rate (arena_02 ≈ 33%). That is the signature of "too few, too similar" labels: the body axis is easy, but left/right wing is not learned. The fix is not more epochs — it is more, more diverse labels, targeted at where the model fails.

The loop: label → train → find failures → repeat

Do not try to label a perfect set up front. Bootstrap with a pilot, then let the model tell you what to label next (active learning). Each round takes ~30–60 min and the flag rates drop fast.

1 · label a batch→ 2 · train→ 3 · infer + QC on a fresh clip→ 4 · read the flags, watch the fly-cam→ 5 · label the failures↺
  1. Label a batch. Round 1: ~80–100 frames (diversity sampling). Later rounds: 30–50 frames focused on the failures you found. 
    uv run anytrack-label \
  --video /data/flies/experiment.avi \
  --tracks /data/flies/results/experiment_tracks.parquet \
  --labels /data/flies/results/experiment_labels.json \
  --n 100 --strategy diversity
    Later rounds: rerun with the same --labels to add to the store (it resumes); bump --n to sample more candidates.
  2. Train (bump the run name each round so models are versioned): 
    uv run anytrack-train \
  --labels /data/flies/results/experiment_labels.json \
  --run-name fly5_v2 --epochs 100 --batch-size 16 --device mps
  3. Infer + QC on a clip you did NOT train on (sparse is fine for evaluation): 
    uv run anytrack-run \
  --video /data/flies/other_session.avi \
  --output /data/flies/results/ \
  --pose --pose-model /data/flies/results/models/fly5_v2 \
  --pose-device mps --pose-every-n 5 \
  --qc --qc-overlay-stride 5 --follow arena_02
  4. Read the failures. Open qc_report.html: the confidence plot and the pose-flag rates. Then inspect qc_pose_flags.parquet to list the exact frames that failed, and watch the cropped fly-cam overlay. The frames the model gets wrong are your next labels. 
    uv run python -c "import pandas as pd; f=pd.read_parquet('/data/flies/results/other_session_qc/qc_pose_flags.parquet'); \
print(f[['flag_low_conf','flag_missing','flag_wing_swap','flag_headtail']].mean()); \
print(f[f.flag_wing_swap][['roi','frame']].head(20))"
  5. Label the failures (point the labeller at that clip; label those frames), then go back to step 2. Repeat until the flags plateau (see Evaluating).

What to label (and how much)

Target ~150–300 confirmed frames for a solid model (the pilot's 30 is a proof of concept). More matters less than variety — the diversity sampler stratifies by body angle and size, but consciously cover these axes:

axismake sure you include…
Arenaall arenas (arena_01–04). Per-arena lighting/optics differ; arena_02 was worst — label it extra.
Body orientationflies pointing every direction (the model must not assume "up").
Wing stateboth wings folded, one wing out, both wings out, wings asymmetric. This is where wing-swap is won or lost.
Positioncentre of the arena and pressed against the wall (edge crops are hardest / lowest contrast).
Behaviourwalking, still, grooming, turning sharply (head/tail flips happen on fast turns).
Appearancea few low-contrast / motion-blurred frames so the model is robust.
Balance beats volume: 150 varied frames beat 400 near-identical ones. If the sampler keeps handing you similar poses, sample a bigger --n and skip the boring ones.

Labelling well & consistently

The model learns your convention, so be consistent — inconsistency is indistinguishable from noise.

  • Fixed anatomical definitions. head = tip of the head; thorax = body centre (the tracker's anchor); abdomen tip = posterior tip; wingL/wingR = the wing tips.
  • Left/right is the FLY's, not the image's. wingL is the fly's anatomical left regardless of how it's oriented on screen. Getting this consistent is the whole ballgame for wing-swap (see below).
  • Use the dynamics scrub (, / .) to disambiguate. If you can't tell head from tail or which wing is which in a still frame, step through the ±context window — motion direction and how the wings move make it obvious. Then place on the anchor frame (press 0).
  • Occluded / folded-away wings: mark the node not visible (v) rather than guessing a position. A confident wrong label is worse than a missing one.
  • Skip genuinely ambiguous frames (mark bad with b) — debris, two flies overlapping, total blur.
  • Fix the seed, don't re-place. Points are seeded from the ellipse; nudge them. Faster and more consistent than clicking cold.

The wing L/R problem (our #1 issue)

Wing-swap dominated the pilot's flags, and it will dominate yours. Attack it directly:

  1. Label many wing-extended frames. Folded wings sit on the body midline where L/R is genuinely ambiguous (the QC flag ignores those on purpose). The model only learns L/R from frames where the wings are clearly out to the sides — so those must be well represented.
  2. Be ruthlessly consistent about which tip is wingL vs wingR (fly's frame). A handful of swapped labels teaches the model to swap.
  3. Lean on the built-in symmetry. The skeleton declares wingL↔wingR symmetric, so horizontal-flip augmentation correctly swaps them — this effectively doubles your wing data if your labels are consistent.
  4. The w key in the labeller swaps the two wings on the current frame — handy when you catch yourself having placed them backwards.
  5. Watch arena_02. If one arena's wing-swap stays high after others improve, its optics/contrast differ — label proportionally more frames from it.

Head/tail flips are the same story for the body axis: label frames where the fly reverses or turns hard, and use the scrub to get the direction right.

Training settings

Defaults are tuned for this setup; change them deliberately.

flagguidance
--epochs50 for a pilot, 100–200 for a real model. With few frames, more epochs mostly overfits — add labels before adding epochs.
--batch-size16 is a good default on MPS (also the fastest inference batch). Lower only if you hit memory limits.
--devicemps on Apple Silicon.
--backboneunet (default) is plenty for 96 px crops. Try unet_medium_rf only if a well-labelled model still underfits.
--val-fraction0.1 default. The report writes training_config.yaml + a training_log.csv — watch validation loss stop improving (that's your epoch budget).
augmentationbrightness/contrast + rotation + translate are on by default (translate makes the model tolerant of the tracker centroid not sitting exactly on the anchor). Usually leave as-is.
Symptoms: train loss low, val loss high / flags bad → overfitting → add diverse labels. Both losses high → underfitting → more epochs or a bigger backbone.

Evaluating: is it good yet?

Judge on a clip the model did not train on, using QC (from anytrack-run --pose --qc or anytrack-qc --pose):

signalgood target
keypoint confidence (median)> ~0.8, stable over time (no long low stretches)
flag_wing_swaplow single digits % (was ~14% at pilot)
flag_headtail≲ 1–2%
flag_low_conf / flag_missinga few % — spikes point at hard frames to label
fly-cam overlay (--follow)skeleton sits on the fly every frame; wings on the correct sides

Stop when the flags plateau across rounds (extra labels stop moving them) and the fly-cam looks right. Then run pose on the full dataset. Check throughput/settings with anytrack-bench --pose if speed matters.

Rule of thumb. Round 1 (~100 frames) gets you a usable model; 2–3 targeted rounds (~200–300 total) get you a good one. The failures the QC flags surface are always the highest-value frames to label next.

Checklist

  • ☐ Pilot: ~100 diverse frames across all four arenas.
  • ☐ Wing-out frames well represented; L/R consistent (fly's frame).
  • ☐ Occluded wings marked not-visible; ambiguous frames skipped.
  • ☐ Trained (versioned run name), inferred + QC on a held-out clip.
  • ☐ Read qc_pose_flags.parquet; labelled the failure frames.
  • ☐ Repeated until wing-swap in low single digits and the fly-cam looks right.
  • ☐ Extra attention to arena_02 (worst optics in the pilot).
